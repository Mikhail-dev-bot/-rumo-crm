## Загрузка фото (Cloudinary)
Эндпоинт `POST /api/upload` принимает `{ "image": "data:image/jpeg;base64,..." }`, загружает картинку в Cloudinary и возвращает `{ "url": "https://res.cloudinary.com/..." }`.
Нужны переменные окружения на сервере (Render → Environment):
`CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`.
Без них эндпоинт отвечает 503.

## Авторизация и роли
Вход: `POST /api/auth/login` `{ "login", "password" }` → `{ token, user }`. Дальше заголовок `Authorization: Bearer <token>`.
Токен живёт 12 часов, роль и имя берутся из бина пользователей при каждом запросе.

| Роль | Что может |
|---|---|
| master | всё: CRUD по всем сущностям, аналитика, управление пользователями (`/api/users`) |
| mechanic | читать данные, менять статус заказа, отправлять диагностику, загружать фото |
| client | видеть только своё; создавать заявки и автомобили (служебные поля задаёт сервер) |

Новые переменные Render → Environment: `BIN_USERS` (ID бина с пользователями), `JWT_SECRET` (длинная случайная строка, 32+ символов).
Без них все `/api` отвечают 503 (закрыто по умолчанию).

Стартовые пользователи: `node scripts/make-users.js clients.json ./out` → `users.json` (кладётся в бин, хэши) и `passwords.txt` (не коммитить).
Тесты: `node --test test/auth-access.test.js`.

## Регистрация клиентов
- `POST /api/auth/register` (без токена) `{ name, phone, password }` → создаёт клиента и аккаунт, сразу возвращает `{ token, user }`. Не больше 5 попыток в час с одного адреса. Роль всегда `client`.
- `POST /api/users/client` (только мастер) `{ name, phone, email? , password? }` → создаёт клиента; если пароль не указан, генерируется и возвращается один раз. В CRM: вкладка «Клиенты» → «Добавить клиента».
- Телефон принимается как `8999…`, `7999…`, `999…` или `+7 999 …`, логином становится `+7999…`.

## Пробег
- Мастер: CRM → «Автомобили» → «Изменить пробег» (можно и уменьшить, если ошиблись).
- Клиент: в приложении «Обновить пробег» (`PATCH /api/cars/:id`, только своя машина, только поле `mileage`, уменьшать нельзя).
- Механик: поле «Пробег на осмотре» перед диагностикой; уходит в `POST /api/orders/:id/diagnostics` как `mileage`, записывается в заказ и обновляет машину, если он больше прежнего.
